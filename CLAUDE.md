# Dope Icons — working rules for Claude

This repo is the source of truth for the Dope Icons set. You test, fix, edit and draw icons here.
Be strict and honest with the owner: if a request isn't standard UI-icon practice or doesn't make
sense, say so plainly and propose the standard alternative instead of silently doing it.

## Where things live

- `icons/<name>.json` — **master files, the only thing you edit.** One per icon.
- `config.json` — grid, padding, base stroke, weights, corner radii, styles.
- `lib/` — geometry (`path.js`), variant generation (`variants.js`), checker (`lint.js`). Shared by scripts and the studio.
- `requests.json` — the owner's queue of requests from the studio.
- `reference/dope-icons-0.1.0.json` — the original pen.dev export, for comparison only. Never edit.
- `dist/` — generated by `npm run build`. Never edit, not committed.

## Commands

```
npm run lint [-- name …] [--rule id] [--all]   # check; exits 1 on errors
npm run fix  [-- name …] [--dry]               # safe mechanical fixes
npm run build                                  # dist/ (refuses on lint errors)
npm run sheet -- name …                        # sheet.html: every variant, 24px + 96px, light + dark
npm run new  -- name                           # blank master
npm run studio                                 # http://localhost:4321 (owner's UI, live-reloads on file changes)
```

Always run `npm run lint -- <names>` after touching an icon, and look at it (`npm run sheet -- <names>`,
then screenshot `sheet.html`, e.g. with Playwright) before calling it done. Never claim an icon looks
right without rendering it.

## Master format

```json
{
  "name": "home",
  "tags": ["house"],
  "lintIgnore": { "off-center": "why it's intentional" },
  "styles": {
    "outline": [ { "name": "body", "paths": [ { "d": "M4.5 9.9L12 3.9L19.5 9.9L19.5 20L4.5 20Z", "stroke": true } ] } ],
    "solid":   [ ... ],
    "duotone": [ { "name": "tint", "opacity": 0.2, "paths": [ { "d": "…", "fill": true } ] }, ... ]
  }
}
```

Path fields: `d`, `stroke`, `fill`, `fillRule` ("evenodd" for cut-outs), `strokeWidth` (omit = base 1.5),
`radius` (corner multiplier, omit = 1, 0 = never round), `sharpNodes` (node indices that stay sharp),
`nodeRadius` (`{"node": multiplier}`). Node numbers: the `M` point is 0, each segment end is the next
number, continuing across subpaths (the studio's "Master nodes" overlay shows them).

## Drawing standard (enforced by the checker where possible)

- **24×24 grid, ink inside 2–22** (2px padding). Centre the ink box on 12,12 (±0.5px) unless the
  asymmetry is intentional; then add a `lintIgnore` reason.
- **Draw every corner sharp.** Rounded corner sets are generated from `config.corners` × `radius`.
  Never put small fillet arcs in the master. Real curves (circles, capsule ends, bells) use `A` or `C`.
- Use real arcs/curves, never chains of tiny line segments.
- Outline strokes are all **1.5** (the base). Weights scale every style, solid included.
- Snap horizontal/vertical edges to multiples of 0.25. Prefer whole/half-pixel coordinates.
- Optical size: compare with neighbours. Circles ~ Ø18–20, squares ~ 16–18, tall/wide shapes up to 20 on the long side.
- **Parts** are named, lowercase, kebab-case, and describe the thing (`body`, `clapper`, `head`, `shaft`),
  not `path`/`path-1`. Outline and duotone use the same part names; duotone adds `tint` first.
- **Solid**: fill the main shape (`fill: true` plus `stroke: true` with the base stroke so it matches the
  outline's footprint) and cut details out with `fillRule: "evenodd"`. Pure line icons (arrows, check,
  plus) stay strokes with `strokeWidth: 2.25`.
- **Duotone**: outline + a `tint` part (filled, `opacity` 0.2) covering the main enclosed area. Pure line
  icons have no tint.
- Names: lowercase kebab-case, one word per concept across the set (don't mix chat/comment, close/x).

## Processing studio requests

When the owner says "process the studio requests" (or similar):

1. Read `requests.json`. Work through every item with `"status": "open"`.
2. Do the work in `icons/`, then lint and render what you changed.
3. Update the item: `"status": "done"` and a short, honest `"note"` (what changed, anything you
   disagreed with). If you need a decision first, set `"status": "question"` and ask in the note.
4. Commit with a message listing the icons touched.

New-icon requests: draw an original design that matches this set's construction (grid, stroke, corner
logic, part naming, all three styles). Never copy another icon set's paths.
